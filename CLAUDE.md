# Store Ready

A free, open-source tool that tells a mobile developer, in seconds, whether an app build
(`.ipa`/`.aab`/`.apk`) will be rejected by App Store Connect or Google Play because of current
platform rules — before upload. Two implementations share one rule set: a browser-only
TypeScript web app (nothing ever uploaded) and a Swift CLI (`storeready`) with byte-identical
JSON output. Full spec: `docs/BUILD_BRIEF.md`.

## Hard constraints (never violate — from the brief §4)

1. Nothing leaves the device. The only network requests the web page ever makes are same-origin
   `GET`s for its own static assets: no `fetch`/XHR/WebSocket/beacon from app code, no third-party
   scripts, fonts, CDNs, or analytics. Enforced by CSP and an automated Playwright test.
2. Analysis runs in a Web Worker; the main thread only renders.
3. Data-driven rules: no rule thresholds or dates hard-coded in parser or UI code. Every rule has
   a source URL and a retrieved date, in `rules/rules.json`.
4. Parity: TypeScript core and Swift CLI produce byte-identical normalized JSON for every fixture.
5. Determinism: injectable clock ("as of" date); stable sort; no randomness in output.
6. No real third-party app binaries in the repo. Fixtures are synthetic, generated by committed
   scripts.
7. Licences: MIT for this repo; vendored Apache-2.0 `.proto` files keep their headers and are
   listed in `THIRD_PARTY_NOTICES.md`.
8. Free to run: public repo, GitHub Actions standard runners and GitHub Pages only.
9. Wording: "Not affiliated with Apple or Google."
10. Every commit is linted and tested via git hooks (lefthook). Never bypass them (`--no-verify`,
    `git commit -n`, `LEFTHOOK=0`, changing `core.hooksPath`). Fix a wrong/slow hook in its own
    commit instead.

## Repo map

```text
rules/            rules.json + seed data: single source of truth, dated and sourced
schema/           report.schema.json, rules.schema.json
packages/core/    TS, no DOM: zip reading, parsers, rules engine, report builder
apps/web/         Vite + vanilla TypeScript UI, Web Worker, PWA
cli/              Swift package: StoreReadyCore (library) + storeready (executable)
proto/            vendored aapt2 / bundletool .proto files
fixtures/         generators (TS), generated fixtures, golden expected reports
e2e/              Playwright tests (also the post-deploy smoke test)
scripts/          verify, check-repo, sync-rules, gen-rules-doc, conformance, test-git-hooks
docs/             SPEC, ARCHITECTURE, RULES (generated), TESTING, CI-CD, PRIVACY, adr/
```

## Commands

- Install (and install git hooks): `npm ci`
- Dev server (web app): `npm run dev`
- Lint, zero warnings: `npm run lint` · fix: `npm run lint:fix`
- Format: `npm run format` · check only: `npm run format:check`
- Typecheck: `npm run typecheck`
- Unit tests: `npm run test:unit` (alias `npm test`)
- End-to-end tests: `npm run test:e2e`
- Swift build: `swift build --package-path cli` · test: `npm run test:swift`
- Conformance (TS core vs Swift CLI JSON on every fixture): `npx tsx scripts/conformance.ts`
- Generate fixtures: `npx tsx fixtures/generators/<name>.ts`
- Sync rules into the Swift package resources: `npm run rules:sync`
- Regenerate `docs/RULES.md` and the README rules table: `npm run rules:doc`
- Everything CI checks, fast: `./scripts/verify.sh` (add `--full` for e2e + the git-hooks
  self-test)

## Coding conventions

- TypeScript strict mode, no `any`.
- Parsers are pure functions returning typed results — never throw on malformed/truncated input.
- `packages/core` has no DOM and no Node built-ins: it runs inside a browser Web Worker.
- Swift 6 strict concurrency.
- Rule checks are small pure functions keyed by rule ID; thresholds and dates come only from
  `rules/rules.json`.

## Definition of done for any change

Tests (unit, plus fixtures + golden files where a rule or parser changed) + docs updated + TS/Swift
parity maintained + `./scripts/verify.sh` passes. Never weaken a test, lint rule, or coverage gate
to make a change pass.

## Never do this

- Never hand-edit `docs/RULES.md`, the README rules table, or generated proto code — regenerate
  them (`npm run rules:doc`, `npm run rules:sync`, the proto codegen script once it exists).
- Never commit an app binary (`.ipa`/`.aab`/`.apk`/`.xcarchive`/`.dSYM`) outside `fixtures/files/`.
- Never bypass the git hooks.
